# Security Audit — 0xhermexVM — 2026-10-20

## Summary

Fork of **9qeklajc/hermexVM** (identified from commit authors and README clone URL): a pnpm/turbo monorepo with an Android/web client (`apps/hermes-chat`, Capacitor) and a local Nostr/ContextVM bridge (`apps/hermes-bridge`) to a Hermes Agent `tui_gateway`. Security posture in-repo is unusually good for this class of project: bridge keys are recommended via an owner-readable key file rather than `.env`, the client allowlist (`CONTEXCGI_ALLOWED_NPUBS`) fails closed at startup, `HERMES_BRIDGE_PUBLIC=false` + `HERMES_BRIDGE_REQUIRE_ENCRYPTION=true` by default, `.gitignore` covers keys/keystores/credentials comprehensively, and the release workflow keeps the Android signing keystore in GitHub Actions secrets and fails closed when absent. No committed sensitive material found. The fork is exactly in sync with upstream.
